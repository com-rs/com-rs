# comrs against OptiCommPy

Machine: Apple M6, 12 cores, Darwin 27.0.0; Python 3.12.15, NumPy 2.5.4, numba 0.68.0, OptiCommPy 0.11, comrs 0.2.0.

Best of a few runs after a warm-up (numba compiled), one thread for comrs; generated by
`python benchmarks/bench_opticommpy.py`.

| Operation | OptiCommPy | comrs | Speed-up | Same result |
|---|---:|---:|---:|:---:|
| split-step Fourier, 5 x 80 km, 800 steps, 65536 samples | 1.27 s | 559.3 ms | 2.3 | yes |
| split-step Fourier in f32, same link | 1.27 s | 333.0 ms | 3.8 | yes |
| linear fibre channel, 1048576 samples | 28.0 ms | 14.9 ms | 1.9 | yes |
| FIR filter, 1024 taps, 262144 samples | 4.3 ms | 2.3 ms | 1.8 | yes |
| blind phase search, B = 64, N = 35, 32768 symbols | 12.3 ms | 7.1 ms | 1.7 | yes |
| Viterbi-Viterbi, 32768 symbols | 1.0 ms | 0.3 ms | 3.4 | yes |
| decision-directed PLL, 32768 symbols | 1.4 ms | 0.8 ms | 1.7 | yes |
| Gardner clock recovery, 65536 samples | 20.4 ms | 0.4 ms | 47.1 | yes |
| adaptive equaliser (CMA, 15 taps), 32768 symbols | 21.2 ms | 1.5 ms | 14.0 | oracle tests |
| BER, SER and SNR (fastBERcalc), 64-QAM, 1048576 symbols | 64.1 ms | 7.0 ms | 9.1 | oracle tests |
| GMI (monteCarloGMI), 16-QAM, 32768 symbols | 6.8 ms | 7.2 ms | 0.9 | oracle tests |
| Monte Carlo BER campaign: 16-QAM, 8 points x 100 blocks of 4096 symbols, one thread | 331.8 ms | 74.3 ms | 4.5 | yes |
| same campaign, 12 cores | 331.8 ms | 12.0 ms | 27.6 | yes |

"Same result" compares the outputs to 1e-6 relative (1e-4 for the single-precision split step and the
Gardner loop, which OptiCommPy computes in complex64); "oracle tests" marks the cases compared value by
value in tests/test_oracle.py instead (the equaliser runs here in the time domain and double precision
on both sides for a like-for-like comparison). The campaign compares the BER of the two implementations.
