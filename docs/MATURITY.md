# Maturity of the modules

For every module a user sees, the strongest evidence that it is right, the tests that
give it, and what is not covered yet. Built from the tests of the repository (the
`literature` unit tests, `validation/tests/*.rs`, the specifications with `expect`,
the Python tests); re-check it when a validation is added.

**Levels.**

- **A** — validated against an external reference: a published figure or table, a
  table of a standard reproduced verbatim, or the recorded output of a reference
  implementation (OptiCommPy 0.11, GNPy 3.0, AFF3CT v4.7.1) on the same inputs.
- **B** — against a closed form only.
- **C** — self-consistency only: round trips, invariants, comparisons between the
  blocks of the library.
- **—** — not validated.

A level says what is checked, not that every regime is: the last column lists the
regimes and references not covered, from the statuses "needed" and "next" of
[`references/README.md`](../references/README.md). Tests marked "ignored" run with
`cargo test --release -p com-validation -- --ignored`, by hand or by the workflow
`validation.yml` started by hand (never automatically); the others run on every push. A specification run "on demand" is checked by `comrs verify <file>`
(`just validate` for `specs/validation/`).

Summary: 32 modules at A, 13 at B, 8 at C.
