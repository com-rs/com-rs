# Code review: redundancy, separation of concerns, reuse, consistency — 30 October 2026

Seven read-only reviews of the whole repository at commit 21af3f7, one per slice
(detailed reports with file and line in [`2026-10-30/`](2026-10-30/)), plus automated scans.
About 190 findings; each was checked against the code by its reviewer, and five were
reproduced by running the code (`Dbp` on an empty field, `Field::inv(0)`, `Rng::below(0)`,
`spec.load` on a missing path, the benchmark paths). This report groups them by theme
and priority, after the audit of 29 October ([`2026-10-29-code-audit.md`](2026-10-29-code-audit.md)),
whose fixes all reviewers found in place, each with its regression test.

**Verdict.** The base is sound:
- no layer violation, no `unsafe`, and no TODO;
- every `Result` documented (315 of 315 public functions have `# Errors`);
- formulas in LaTeX with their reference, and tests named after the papers;
- determinism kept (one stream per trial, records merged in order);
- parameters of the spec blocks declared once (`block_params!`).

The weak points are no longer correctness bugs but what the request names, in this order:

1. **Kernels written several times** (about 45 cases), most of them in the validation
   tests and the Python layer, some in the library (the bitwise demapper four times, the
   optical span loop five times).
2. **Missing shared abstractions**, which push each module to write its own: no soft-output
   decoder trait, no fading-channel trait, `Modulate` implemented by half the waveforms, two
   builder signatures in com-spec.
3. **Uneven API conventions** (units in names, argument order, error variants, antenna
   layout in Python): section 5 of the previous audit, still open, now with a full inventory.
4. **A dozen silent wrong results or panics**, all small to fix.

## 4. Missing shared abstractions (reuse)

1. **There is no shared soft decoder.**
   - LDPC, BCJR, turbo and `NrLdpc` each produce or discard a posteriori LLRs in their own shape, and `Punctured` cannot pass them on.
   - Fix: `trait SoftDecode` in `com_fec::block` (`app_into`), with `ListDecode` apart.
2. **The waveform verbs are half implemented.**
   - CE-OFDM and FBMC do not implement `Modulate`/`Demodulate`.
   - The OFDM, UFMC and OTFS impls invent sample rates (`Hertz(L)`, `Hertz(1.0)`), and no `demodulate_into` checks the input rate.
   - Index-symbol waveforms (CSS, CPM) need an ADR.
3. **The channels share no shape.**
   - Each one has its own constructor shape, and `draw` returns four different types.
   - Fix: a `Fading` trait and parameter structs. The copied `fade` and `Propagate` bodies then disappear.
4. **OTFS takes an anonymous copy of `com_channel::multipath::Path`.** Fix: move `Path` to `com-core`.
5. **com-spec has two builder signatures**, one for built-in blocks and one for extensions, and each family re-matches on the name. Fix: one builder per `BlockInfo`, with the extension signature.
6. **The units have two sources.** The newtypes `Db`, `EbN0` and `EsN0` have no caller outside their file, while `db2lin` is used 109 times. Choose one source, or retire the newtypes with an ADR.
7. **DBP's exact inverse relies on a float floor test** shared with com-channel, which lowers the forward step by ULPs to make it pass. Fix: pass the forward step plan explicitly and compare integers.
8. **Missing inverses and workspaces:**
   - `nr::demodulate`;
   - `Demap::llr_into`, since the demapper allocates;
   - a `Fir` that keeps its spectrum;
   - an `Ostbc` stored in the receiver instead of rebuilt per block.

## 5. Consistency of the API (section 5 of the previous audit, inventory)

- **Units in names.** Rust:
  - linear SNRs without `_lin` in `ofdm::sync`;
  - `Numerology`, `phase_noise(ts)`, the converter frequencies, `wdm_grid(spacing)`;
  - `Laser.linewidth_hz: f64` against `PhaseNoise.linewidth: Hertz`;
  - `Photodiode.dark_current` and `temperature_c` against `PinFetReceiver.background_current_a` and `temperature_k`;
  - `Cdl.carrier_frequency`, `velocity` and `delay_spread`, while the spec and Python already say `fc_hz`, `velocity_mps` and `delay_spread_s`.

  Spec blocks: cfo `hz`/`omega`, `sigma`, `tau1`/`tau2`, `max_nl_phase`, a cdl `spacing` given in wavelengths, `coherence`.

  Python: `freq_shift(delta_f)`, `delay_fft(delay)`, `aclr_db`, `gn_model(symbol_rate)`, and others.
- **Argument order.** Some constructors take (n, k): `PolarCode::new`, `LdpcCode::peg`, `normal_approximation`. Others take (k, n): `NrLdpc`, `NrPolar`. In RS, the constructor is `shortened(m, t, n)` but the closed forms take `(n, t, …)`. In Python, the generator argument moves from first to last place.
- **Opposite boolean polarity** for one choice: `exact` in `max_star`, BCJR and turbo, but `max_log` in `Constellation::llr`. Fix: a `Jacobian { Exact, MaxLog }` enum.
- **SNR conventions under one name:** `ser`/`ber` mean Eb/N0 in com-mapping, Es/N0 in CE-OFDM and per-sample SNR in CSS.
- **Error variants:** the same length mismatch is `Config` here and `Shape` there (NR, `message_passing` against `detection`, `frame.rs`, `stability`, interpolation), and some docs promise the other variant.
- **Constructors take different shapes:** `new -> Result` with struct update, positional lists of 5 to 8 arguments, or no constructor at all. `Css::lora`, `Rapp`, `Saleh` and `Mzm` are never validated.
- **Unnamed tuples:**
  - in com-spec: `Spec::skip_below`, `Check::measured`;
  - in the readers and metrics: `read_samples`, `monte_carlo_gmi`, `m2m4`;
  - in theory and slicing: `TheorySetup`, the 5-tuple grid of the slicer;
  - (estimates, variances) comes in three shapes.
- **Containers:** `stream` returns a view on `Symbols` but a slice on `Signal`; `resize` against `reshape`; `len` against `n_samples`.
- **Vocabulary:**
  - `sps`, `oversampling` and `samples_per_symbol` for one notion;
  - `alpha` against `rolloff`, and `sigma2` against `noise_var`;
  - `n_data` with three meanings;
  - `demodulate_with` with two meanings.
- **Python, specifically:**
  - The antenna layout is `(n, n_rx)` for detection, `(n_tx, slots)` for STBC and `(n_tx, n)` for fading. This is high priority and breaking.
  - Some return types depend on the arguments.
  - `theory_*` functions are scalar-only or lack the prefix.
  - Rust and Python names differ for the same item.
  - 22 classes have no `__repr__`, and nothing is picklable (`Rng` matters for multiprocessing).
  - 222 of 237 fallible bindings have no `Raises:` section.
  - Exceptions are uneven: `TypeError` where `ValueError` is expected, and `OverflowError` on a negative `n`.

## 6. Performance (measure before, show results unchanged after)

The hot spots fall into three groups:

- **Rebuilt or re-checked on every call:**
  - Alamouti rebuilds and re-checks its code for every block;
  - `Css::modulate` validates and recomputes M·J `cis` per symbol;
  - `Mimo::draw` re-validates once per sample at `coherence = 1`;
  - `KBest`, AMP and OAMP re-check their arguments on every call.
- **Extra work and allocations in loops:**
  - `SplitStep::run_with_gain` does 4 FFTs per step instead of 2, on every Raman span;
  - `ManakovSplitStep` and `AdaptiveEqualizer` allocate per step or per sample;
  - LDPC rebuilds its edge offsets per frame and re-verifies Hc = 0 on every encode;
  - the DVB-S2 data positions are rebuilt per frame;
  - `log_priors_of` allocates per channel use;
  - `profile_of` builds the whole link just to get its labels.
- **Costly algorithms:**
  - `delayed_correlation` and `windowed_energy` are O(nW); running sums would fix this, but rounding changes, so the cards must be re-checked;
  - the polar reliability runs a 100-step bisection n log n times;
  - `min_distance2` has no bound on (2M−1)^N.

## 8. Recommended order

1. **Correctness batch** (§1). Each item is small and gets a regression test:
   - `Spec::runner`, shared by the three callers;
   - confidence validation, with the spec's confidence passed to the precision targets;
   - `PerPol` training, with a trainable extension block in the test;
   - the theory context and its case handling;
   - RS `n`/`k` in Python;
   - `viterbi_viterbi` and `ddpll`;
   - `Dbp` on an empty field;
   - the constructor checks, the grid duplicates and the benchmark paths;
   - the four Python items.
2. **Shared kernels** (§2), each with a bit-identity test (ADR 0005):
   - the demapper kernel and `llr_into`;
   - `com_validation::{until_errors (on com_sim::Runner), fer, sweep_crossing}`, replacing 13 loops;
   - the optical span driver;
   - `normalized_correlation`, `lentz`, `Laser::carrier`, `ResourceGrid::data_indices`, `BitSelection`;
   - the Python test helpers.

   Also extend `--duplicates` to types.
3. **Placement moves** (§3): file moves with re-exports, so nothing else changes.
4. **Abstractions** (§4): `SoftDecode`, the waveform verbs (with an ADR for index symbols), `Fading`, `Path` in com-core, one builder signature, and nested groups through `block_params!`.
5. **The breaking API batch** (§5) in one release, with aliases kept one release and a migration table in the CHANGELOG. The order inside the batch: units, then (n, k), then `Jacobian`, then error variants, then the Python antenna layout and `theory_` names.
6. **Performance** (§6), item by item, after a profile. Show the results before and after.
7. **Maintainability** (§7): splits, long functions, constants, doc fixes, validation files renamed and moved to cards.
