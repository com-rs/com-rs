Why com-rs
==========

.. generated by tools/highlights.py from the repository: do not edit

Four properties, each measured from the files of the repository rather than
claimed: the numbers below are recomputed by ``tools/highlights.py`` and checked by
``just check`` (see *Updating* at the end).

- **Lightweight**: one run-time dependency in Python (numpy), 9 direct crates in Rust and no C, C++ or Fortran library to build; 27 MB installed with its dependencies (the benchmark's environment: komm 22 MB, OptiCommPy 321 MB, Sionna 1004 MB).
- **Fast**: compiled Rust, Monte Carlo runs on every core; on one CPU thread, the links of the benchmark take 2.1 to 33 times as long with komm, 2.3 to 4.7 times as long with OptiCommPy and 1.1 to 7.4 times as long with Sionna as with com-rs.
- **Safe**: ``unsafe`` code forbidden in every crate, invalid inputs are errors (one error type), results independent of the thread count; 571 unit tests, 151 validation tests, 235 Python tests.
- **Validated**: compared with 105 papers, standards and reference tools (67 fully reproduced, 32 partly), 59 inconsistencies found in them; 60 validation cards rerun a comparison without the paper.

Lightweight
-----------

The Python package needs ``numpy`` only at run time (matplotlib is optional, for the plots). The Rust library uses 9 crates of the Rust ecosystem: ``ndarray``, ``num-complex``, ``rayon``, ``rustfft``, ``serde``, ``serde_json``, ``serde_norway``, ``thiserror``, ``toml``. It links no BLAS, LAPACK or FFTW and builds no C, C++ or Fortran code: the special functions, the quadratures, the linear algebra and the solvers are written in the library, so that ``cargo build`` works on any platform with Rust alone and the results do not change with the version of a numerical library. In ``Cargo.lock``, which also covers the bindings and the benchmarks, the only crates that bind a system library are ``windows-sys``, the operating-system interfaces of Windows.

Safe
----

Rust checks memory safety at compile time, and ``unsafe`` code is forbidden in every crate of the library (``unsafe_code = "forbid"`` in the workspace lints; the Python extension excepted, whose PyO3 macros expand to it). An invalid input — a negative variance, lengths that differ, a parameter out of range — returns an error of one shared type, raised as ``ValueError`` in Python, instead of a wrong result or a crash. Random blocks draw from explicit, reproducible streams: the same seed gives the same result on 1 or 12 threads. Clippy runs in its pedantic mode with every warning an error.

Validated
---------

Every module is compared with an external reference: the figures and tables of
papers, the tables of standards, the recorded outputs of reference
implementations (OptiCommPy, GNPy, AFF3CT, Sionna, py3gpp), in tests named after
the reference. The comparisons that are rerun without reading the paper again
are written as :doc:`validation cards <comparisons>` (``just card <id>``).

Updating
--------

The numbers of this page come from files that scripts regenerate:

.. code-block:: bash

   just bench-libraries               # the benchmark and the footprint (quiet machine)
   python tools/literature_table.py   # after editing validation/literature.yaml
   python tools/maturity_table.py     # after editing validation/maturity.yaml
   python tools/highlights.py         # this page and the front pages

``just check`` fails when one of these pages is older than its sources.
